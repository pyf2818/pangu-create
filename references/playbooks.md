# 领域手法库（Domain Playbooks）

> 这不是领域分类学，是**知识编码手法库**。各预组合节是手法按常见产出形态的示例组合——领域本身不受限，「万物皆可」靠的是手法自由组合与同类侦察，不是把领域塞进固定的盒子里。

## 用法（三档）

1. **常见形态**：定位命中某一节 → 直接用该节做起点
2. **跨领域**：按产出形态取一节为主，按知识类型叠加另一节的手法（如「金融研报生成」= 剧本二的黑盒脚本+反俗手 ⊕ 剧本四的证据标签+负面边界）
3. **全新/陌生领域（各预组合节都对不上）→ 完全正常**：走 [forge.md](forge.md) F1.0 同类技能侦察——搜 GitHub/全网找 2-4 支同类或相邻领域 skill，完整读源码，从吸收表提取手法组合成该领域自己的组合；确无同类时用下面的两轴表自行组合

**负重维度选型**：每个预组合该在哪些质量维度上全优（功能/稳定性/性能/观感/安全/可进化/兼容/成本八维），映射表见 [quality-dimensions.md](quality-dimensions.md)——多维全面考虑从这里开始，不许只盯着功能单一维度。

## 两轴组合表（无预组合可循时的生成器）

| 产出形态 ↓ / 知识类型 → | 程序性（怎么做的步骤） | 事实性（是什么的参考） | 判断性（好差的品味） | 风险性（什么不能碰） |
|------------------------|---------------------|---------------------|--------------------|-------------------|
| **文档/文件产物** | 工作流 + 黑盒脚本（剧本二） | references 速查（剧本六切片法） | 反俗手清单 + 二次精修（剧本二） | 质量地板 + 交付前 checklist（剧本二） |
| **代码/工程行为** | 铁律 + 工作流（剧本一） | 模式库索引（剧本六） | 形态匹配（剧本一） | 合理化对照表 + 红灯清单（剧本一） |
| **判断/建议输出** | 完备性维度清单（剧本四） | 数据事实分离（剧本四） | 统治性原则句 + 流派分歧（剧本四） | 负面边界 + 证据四标签 + [VERIFY]（剧本四） |
| **环境/浏览器操作** | 决策树 + 侦察-再-行动（剧本五） | 选择器与等待规则（剧本五） | —— | 不可逆动作确认清单（剧本五） |
| **多媒体/时空产物** | 状态路由表 + 渲染管线（剧本三） | 参考文档切片（剧本六切片法） | Hard Rules 与工作示例分离（剧本三） | 物理量实测 + 自检上限（剧本三） |

用法：定位确定产出形态与知识类型后，取行列交叉处的手法组合；同一格内多个手法按需取舍。

## 剧本一：工程方法类（TDD、调试、评审、验证纪律）

**本质**：对抗 AI 的「合理化堕落」——AI 知道规则，但压力下会找借口绕过。

| 手法 | 写法 |
|------|------|
| 铁律 + 铁律名 | `NO PRODUCTION CODE WITHOUT A FAILING TEST FIRST` 式大写铁律单独成节，配「违反字面 = 违反精神」原则 |
| 合理化的对照表 | 把测试中抓到的每个借口写成两列表：`借口 \| 现实`。借口必须来自真实测试（RED 阶段记录的原文），不是编的 |
| 红灯清单 | 「出现这些念头 = 停下来重来」：列自我合理化的触发语（「这次不一样因为…」「我已经手动测过了」） |
| 形态匹配失败类型 | 纪律违规 → 禁令+合理化表；产出形状不对 → 正面配方（说清产出是什么、由哪些部分按什么顺序组成）；漏元素 → 模板里的必填槽位；条件行为 → 可观察谓词的条件句。**对形状问题用禁令会适得其反**（实证：禁令组的违禁产出反而更多） |
| 压力测试 | 用「时间压力 + 沉没成本 + 权威催促」叠加场景测 agent 是否守规矩 |

**验证方式**：压力场景测试（见 testing.md），红绿循环：先抓基线违规原文 → 写 skill 针对性封堵 → 重测 → 封新漏洞。
**范例**：obra/superpowers 的 `test-driven-development`、`systematic-debugging`、`verification-before-completion`。

## 剧本二：产物生成类（Word/Excel/PPT/PDF、海报、长文）

**本质**：产出是文件，对错可机检，品味靠约束与反俗手。

| 手法 | 写法 |
|------|------|
| 黑盒脚本承担确定性操作 | 格式转换、校验、打包全写成 `scripts/` 脚本；正文只写「先 `--help` 再调用」，明确禁止读脚本源码（防止脚本内容污染上下文） |
| 两阶段创作（创意类） | 先写「设计哲学/创作宣言」（.md）→ 再按哲学表达成产物（.pdf/.png/.html）。宣言阶段反复强调「工艺品级打磨」，表达阶段获得解释空间 |
| 反 AI 俗手清单 | 列出 AI 生成的典型俗手（如：奶油色底 + 高对比衬线 + 赤陶橙点缀；万物圆角卡片 + 同款阴影；全大写眉标；标题里单词变色），要求「如果不是 brief 明确要求，不许默认使用」 |
| 计划先行 + 对 brief 自审 | 先出 token 系统（色板 4-6 个命名 hex、字体角色、布局概念、原则），**对照 brief 自问「这个方案是不是我给任何同类 brief 都会出的默认方案」**，是则改，再动工 |
| 质量地板不宣告 | 响应式、可访问性、留白、无重叠——默默做到，不写进卖点 |
| 二次精修 | 产物完成后强制二过：不加新元素，只让已有的更协调（「出门前摘掉一件配饰」） |

**验证方式**：产物机检（脚本验证文件可打开、尺寸正确）+ 视觉自检（渲染成图看）+ 反俗手清单逐条过。
**范例**：anthropics/skills 的 `canvas-design`、`algorithmic-art`（两阶段创作）、`frontend-design`（反俗手）、`docx`/`pptx`/`xlsx`/`pdf`（黑盒脚本模式）。

## 剧本三：视频多媒体类（HTML 转 MP4、动效、剪辑、数学动画）

**本质**：多环节流水线，错误会静默累积，必须机器验证每个环节。

| 手法 | 写法 |
|------|------|
| Hard Rules 与 Worked Examples 分离 | 正确性规则（字幕必须最后合成、段边界必须 30ms 淡入淡出、切点必须吸附词边界）编号为 Hard Rules 单独成节「背下来」；其余全部标注「这是成功案例的工作示例，不是命令」——品味自由，正确性铁律 |
| 状态路由表 | 入口按「项目当前状态」列表，第一行命中即执行，不往下看（有 BRIEF → 续做；有半成品 → 恢复；全新 → 意图访谈） |
| 渲染-自检闭环 | 产出后机器自检：切点处抽帧看画面连续性、量响度（`ebur128`）不靠猜、ffprobe 验时长。**不能听的环节就报数字，不装能听** |
| 自检不过不见人 | 自检通过才展示给用户；自检上限 3 轮，仍有问题就标注给用户而不是无限循环 |
| 骂手评审 | 发布级产出 spawn 一个「批评家」子 agent：只许挑错、给带时间码的问题清单和修复优先级，禁止表扬 |
| 并行槽位 | 多个独立动效 = 每槽一个子 agent 并行，prompt 十要素（目标一句话、绝对输出路径、精确技术规格、色板具体值、字体路径、逐帧时间线、反清单、代码模式、交付清单、「不许提问，模糊就选最明显解释」） |
| 确定性渲染 | 组合是 HTML、时间线可 seek、渲染结果逐帧确定——脚本管流程，AI 只管创作决策 |
| **视觉设计阶段必做** | 构建前单独一步：定 5-6 色板 token + 每屏视觉锚点规划 + 动效模式选型（≥3 种进阶模式）。**品味层必须有「正向标准」与俗手清单两份**——只有禁区没有正向标准时，AI 会掉进俗手（实战教训：near-black+单点缀被用户判丑，正因只抄了俗手清单没立正向标准） |
| **旁白/音画同步协议** | TTS 逐段生成 → ffprobe 实测每段时长 → 时间轴从旁白推导（段时长 = 旁白 + 呼吸）→ mux + loudnorm。顺序不可颠倒：先有旁白再定时间轴 |
| **视觉品质评分锚点** | 出厂自检除正确性外逐屏打勾：每屏有锚点 / 配色过俗手清单 / 动效 ≥3 种且不乱 / 音画对齐——不过 = 软性失败必须修 |

**验证方式**：每帧/每切点机检 + 响度等物理量实测 + 批评家子 agent。
**范例**：heygen-com/hyperframes（状态路由 + 领域 skill 懒加载）、browser-use/video-use（Hard Rules + 自检闭环）、manim-video（模式表 → 参考文档映射）。

## 剧本四：领域专家类（金融分析、教育设计、法律、医疗、咨询）

**本质**：产出是判断与文档，「完成」是判断题不是执行题。领域伤害不可逆（错估值、错试题），所以压制性规则与可溯源性是这类的生命线。

| 手法 | 写法 |
|------|------|
| 统治性原则句 | 开篇一句话给模型戴上行业世界观：「每份 CIM 都是销售文档，要当销售文档读」「单一估值方法必然是错的，三角验证才是答案」 |
| 完备性维度清单 | 把老手脑中「必须覆盖哪 N 块」显式成编号清单（如估值必过的五个镜头、CIM 评审必查的七个风险域），**结构上缺任何一块即不完整** |
| 参数级踩坑规则 | 具体到版本号、枚举值、错误码：「某 rig 版本在人形上 0/16 全败」「`Sept` 四字母缩写坑」「DCF 终值 >75% 总 EV = 披着外衣的倍数法」——这是教程查不到、只有烧过才知道的部分 |
| 量化纪律写进工作流 | 每步内嵌参数级标准（敏感性 ±100bps、要求回报 2.5x MOIC/20% IRR 最低线），产出自评有标尺 |
| 方法论分歧解读 | 「DCF>comps 意味着什么」对照表——教模型「reconciliation 才是洞察所在」；领域内流派分歧分列呈现，不假装共识 |
| 失败模式反例库 | Common Failure Modes 用「症状 + 定性」写出让模型自检：「先有结论再拼区间」「对各方法取平均是智识空虚」 |
| 证据四标签 | 每个关键数字必须标注 `SOURCE FACT / DERIVED / ASSUMPTION / UNRESOLVED` 之一并带来源定位——禁止把假设写成事实 |
| 负面边界（三层防越权） | ① frontmatter 写反触发表（「不用于只想快速获得答案的请求」）② 正文写 Never use it to 清单（「绝不用于静默修复或专业背书」）③ 脚本对越界输入直接 `raise ValueError` 硬拒绝——三层同一边界 |
| 状态标记制度 | 不确定的事实必须带 `[VERIFY]` 标记；缺用户上下文的位置写 `[NEEDS USER INPUT]`——**禁止编造校历/政策/行情填空**；宁可留洞也不从记忆里补 |
| 独立重解题（教育类） | 答案键由独立 agent 重新解题产生而非抄写出题者意图，两键不一致时分歧本身就是要上报的发现，禁止悄悄选一个 |
| 档次化产出模板 | 按场景给交付模板（投资备忘录/尽调清单/教案/习题），每个模板带必填槽位 + 交付前 checklist（10 条 `- [ ]` 验收） |
| 教学类追加闭环 | 学习类 skill 内建「复述 → 追问 → 纠错 → 迁移测试」回路 + 多维掌握度 rubric，每轮只攻一个漏洞，防止无限追问 |

**验证方式**：经典案例回归测试（领域公认案例跑 skill 对比公认结论）+ 交付前 checklist + 合规边界测试（诱导越界看是否拒绝）。
**范例**：andreworia/claude-finance-skills（统治性原则句 + Five Lenses + Never use it to）、angieruiz17/claude-fintech-skills（症状前置的事故复盘型：每个坑配「预期输出」可自验）、teaching-skills（Course Passport 状态载体 + BLOCK/WARN 分级质量门）、本地 feiman-learning（教学闭环 + 反触发 description）。

## 剧本五：浏览器/自动化类（网页操作、测试、爬取、GUI 控制）

**本质**：环境是别人写的、随时会变，必须侦察先行、失败可恢复。

| 手法 | 写法 |
|------|------|
| 决策树开路 | 入口给一棵「任务 → 分支 → 动作」的决策树（静态 HTML？直接读选择器。动态？服务器在跑吗？没跑 → 起服务器助手），不留给 AI 猜 |
| 侦察-再-行动 | 先导航 + 等待网络空闲 + 截图/DOM 侦察 + 从真实渲染态找选择器，再执行动作；禁止凭源码猜选择器 |
| 黑盒助手脚本 | 服务器生命周期、等待、截图封装成脚本；「先 `--help`，别读源码」 |
| 显式等待写死 | 「等待网络空闲/元素出现」写成硬规则——漏了就是最大静默失败源 |
| 证据留存 | 每步留截图/DOM 片段，失败时凭证据定位而不是重试赌运气 |
| 权限与边界 | 明确哪些动作不可逆（提交表单、支付、删除），列出需要人工确认的动作清单 |

**验证方式**：真实页面冒烟测试 + 失败注入（页面结构变了 skill 会不会正确降级）。
**范例**：anthropics/skills 的 `webapp-testing`（决策树 + with_server.py 黑盒）、browser-use 系列。

## 剧本六：3D/游戏/创意编程类（Three.js、游戏引擎、生成艺术）

**本质**：知识量大且分层（API 细节 → 场景模式 → 引擎机制），必须渐进披露 + 知识库化；「好看/好玩」必须锚定成可评分资产。

| 手法 | 写法 |
|------|------|
| references 知识库按主题切片 + 「何时读」索引表 | 每个主题一个文件（相机、材质、物理、性能），SKILL.md 只放索引表（每行：文件名 + Read it to…）——正文写全 3D 知识必爆 token |
| 同构骨架可预测 | 知识参考型 skill 统一骨架：Quick Start（最小可运行）→ Core（构造签名+注释版代码）→ Common Patterns → Performance Tips → See Also 交叉引用；可预测的结构才能批量校对 |
| 名词域+动词域双覆盖 description | 前半列主题名词（scene setup, cameras, lighting），后半列行为动词（Use when setting up scenes, configuring renderers…）——触发面最大化 |
| 评分锚点资产化 | 把「什么叫 2 分/3 分」打包成真实样例（截图/文档），配 0-3 级锚定描述表——**打分前必须先看锚点**，彻底消灭「我觉得挺好」 |
| 客观指标双保险 | 主观评分外配可测阈值（色彩熵 <3.0 → 材质分不得高于 2、亮度对比 <60 → 扣灯光分），脚本算指标，评分有下限约束 |
| 一票否决项 | 列出自动判负的特征（「HUD 全是矩形统计卡」「用雾和 bloom 冒充已建模几何体」），命中即整单不合格，防止局部达标整体平庸 |
| 证据清单防作弊 | evidence manifest 声明本轮必须捕获的证据集（截图×状态），校验脚本只认本轮新鲜证据——杜绝「拿旧图交差」 |
| 模式库优先于手搓 | 效果/玩法先查模式库，搜不到才手写——防止重造轮子 |
| 引擎契约写死 | 框架结构契约（单时间线、根节点尺寸、id 对应）连同「首次构建必踩的坑清单」放最前面——lint 报错前的最后防线 |
| 花费分段 gate | 生成型管线（3D 资产生成/批量内容）在每个花钱环节 `--stop-after` 停下供人检视再继续，checkpoint 记录任务 ID 防重复扣费 |
| 首单元门 | 批量生成前只做第 1 个单元并过全部检查，才放行批量——批量废品的成本是单件的 N 倍 |
| 审美哲学先行（生成艺术类） | 先写算法哲学/美学运动宣言再让代码表达；种子随机、参数探索、全场景统一色板与节奏作为标准写入 |
| 可玩性自检（游戏类） | 「能玩」是及格线：起能进、死能重开、核心循环 30 秒内可感知；性能预算（帧率红线）写进验收 |

**验证方式**：最小场景跑通（渲染不报错、帧率达标）+ 逐模式回归。
**范例**：CloudAI-X/threejs-skills、majidmanzarpour/threejs-game-skills、anthropics/skills 的 `algorithmic-art`。

## 预组合七：人物/思维蒸馏（把一个人、一个团队、一种思维范式做成 skill）

**本质**：蒸馏的不是「他说过什么」（WHAT they said），是「他怎么想、为什么成为他」（HOW they think）。

| 手法 | 写法 |
|------|------|
| 三重验证的模型层 | 心智模型必须过跨域复现 / 有生成力 / 有排他性（forge.md F2.2），宁少勿多（3-7 个） |
| 灵魂层纵深 | 在认知/决策/表达/价值/谱系/边界之上追问「为什么需要成为他自己」：伤口图谱、执念结构、意义押注、核心矛盾——每个推断标注置信度与依据 |
| 价值观的代价 | 价值层不止列排序，写「坚持这些信念付出了什么代价」 |
| 盲区溯源 | 边界层不止列局限，写「盲区的心理/处境起源」 |
| 矛盾仲裁四分法 | 来源层级 / 时间 / 言行 / 真矛盾四类处置（forge.md F2.5） |
| 灵魂层三重检验 | 可证伪性（找不到反例的推断是伪洞见，删）/ 独立性（删掉灵魂层 skill 仍可用才合格）/ 素材溯源（无据可查的推断 = 硬性失败） |
| Agentic Protocol 从模型推导 | 核实维度从心智模型反推（芒格 → 看护城河与激励结构；塔勒布 → 看尾部风险），不写通用的「搜索相关信息」 |
| 防漂移 | 角色扮演规则 + 表达 DNA 完整保留，防长对话退回通用助手腔 |

**验证方式**：校准测试（已知情境比对公开立场）+ 边界测试（未知推断必须带不确定性）+ 声音盲评（三样本：skill 版 vs 通用 AI vs 本人原话）+ 灵魂层三重检验。
**范例**：alchaincyf/nuwa-skill（骨架与调研体系）、fattly/god-skill（灵魂层、行业专属 Agent、矛盾仲裁）、nuwa-skills/sunzi-skill 等衍生。

## 跨剧本通用组件

不管哪个剧本，以下积木按需配备（F3 构建规范的落地清单）：

1. **test-prompts.json + results.tsv + git 棘轮三件套**：回归考题、优化日志、只进不退的版本链——这三件是把 skill 从「一次性文案」变成「可进化资产」的分水岭
2. **双段式 frontmatter**：做什么 + 名词域/动词域/用户原话触发 + **反触发表**（明确不用于什么，防止误触发与越权使用）
3. **失败分支三段式表**：触发条件 → 一线修复 → 兜底；能自验的坑配「预期输出」（修复后应看到什么）
4. **Agentic Protocol**：问题分类 + 按领域心智模型推导的核实维度
5. **量化验收**：交付前 checklist（`- [ ]` 逐条）或评分表，重要领域加一票否决项
6. **反模式黑名单 + 负面边界**：「不要做」清单每条带为什么；Never use it to 划出权限边界
7. **状态载体（可选三件之一）**：跨阶段/跨会话的事实源——证据 manifest、断点 checkpoint、课程护照等，杜绝「旧证据冒充新证据、重复扣费、静默改数据」
8. **花费/破坏性动作分段 gate**：贵的、不可逆的操作，每段之间设人工确认点
9. **诚实边界**：做不到什么、信息截止日期；知识密集型加 [VERIFY] 标记制度
10. **更新模式**：哪些维度要定期刷新、调研时间标在哪
11. **质量维度卡**：负重维度 × 继承解法 × 本 skill 标准 × 差异化（八维模型，见 [quality-dimensions.md](quality-dimensions.md)）——多维全面考虑的制度化落点
12. **配方库（生成性资产）**：产出物含创作成分的 skill 必须捆绑（`references/effects.md` / `motion-library.md`）——进阶效果模式 + 最小实现骨架 + 代价。范例：html-to-video 的 motion-library、threejs-web 的 effects.md。没有配方库，「正向品味标准」只是口号
