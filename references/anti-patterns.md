# 反模式黑名单（完整表 AP-1 ~ AP-34）

> `SKILL.md`「反模式黑名单」的完整母表。行号與 AP 编号永久锁定（下游测试与文档按编号引用，新增只追加不重排）。

| # | 反模式 | 替代做法 |
|---|--------|---------|
| 1 | description 里总结工作流 | 只写触发条件；工作流进正文 |
| 2 | 用「建议/可以考虑/视情况/灵活把握」写关键步骤 | 写具体操作、参数、格式、示例 |
| 3 | 检查点只靠「建议确认」措辞 | 显式 🔴 CHECKPOINT / 🛑 STOP 视觉标记 |
| 4 | 在同一上下文里改完自己评 | 独立子 agent 盲评 |
| 5 | 为凑分加冗余段落 | 触顶 break，见好就收 |
| 6 | `git reset --hard` 当回滚 | `git revert` 保留可追溯链，或用 `evidence/snapshots/` 定向恢复 |
| 7 | dry_run 数 ≥ full_test 数 | 至少 1 次真实 full_test，且干跑不得多于实测 |
| 8 | 调研文件存到 skill 目录外 | 全部落 `references/research/` |
| 9 | 软化措辞稀释铁律 | 铁律单独成节 + 红灯清单 |
| 10 | 不报成本直接开跑长任务 | Phase 0.5 档位确认 |
| 11 | 创建新 skill 不查共享知识库 | 先查 `research/shared/` 的铁律/反模式/品味信号/待吸收清单 |
| 12 | worse 教训不回填共享层 | 通用教训 → 回填 `evolution-feedback.md` + `iron-rules`/`anti-patterns`/`taste-signals` |
| 13 | 模糊需求不做市场验证直接开造 | 先跑 Phase 0B 市场热度扫描（4 指标）+ 空白地图初探，确认值得做再进入 Phase 0.5 |
| 14 | F1.0 侦察后不画空白地图 | 吸收表落盘后必画覆盖图 + 标记空白点，让用户选择走成熟方向还是创新方向 |
| 15 | 产出型 skill 不做人类可读 README | F3.5 产出 README.md（快速上手 + 示例输出 + 同类对比），让人一眼看到价值 |
| 16 | 深层需求挖掘用问答题不用选择题 | 用「你在哪里卡住了」反推深层需求 + 提供 2-3 个选项让用户选，不做开放式追问 |
| 17 | 用配方数量冒充观感质量 | 「加了粒子/雾/辉光 = 过惊喜线」是把量产件当工艺；改为 ≥2 个非默认招牌手法 + 参数级差距清单（`output-quality.md` 关 2） |
| 18 | 同模板换文案当新作品 | 构图/色板/字体/节奏不改，只换内容 = 模板换皮；必须过反模板测试（≥3 处实质差异） |
| 19 | 作者目检代替盲评 | 「我看了没问题」不是证据；独立 judge 不知道来源、与参照物并排比较才算 |
| 20 | 把同类 skill 的默认模板当美学标杆 | 那不是参照物；美学标杆必须是同类顶级**成品**，拆到参数层 |
| 21 | 用功能清单冒充设计论点 | 「更高效/更专业/更全面」任何同类都能说；必须过竞争测试，写出默认做法失败的具体机制 |
| 22 | 一张截图当范例集 | 截图是证据不是作品；≥3 件可打开/可运行的范例 + 1 件手写署名作品，每件标注示范了哪个论点 |
| 23 | 核心变换全靠散文描述 | 换模型就漂移，也无法复现；核心生成/校验落 `scripts/` + 一键 `verify`/`finalize` |
| 24 | （已并入铁律 13，行号保留防下游 AP 编号错位）承诺不写断言 | 见铁律 13：断言 + 测试 ID + 新鲜回执，写不出就删承诺 |
| 25 | 宣称支持但从不注入失败 | 只跑 happy path 的验收等于没验收；至少注入两类失败并证明提示可见 |
| 26 | 看门狗写在 `type="module"` 里 | 依赖挂了 module 根本不执行，提示永不出现；看门狗放普通 `<script>` 并挂 error 捕获 |
| 27 | 环境抖动当产品缺陷修 / 阈值贴着实测过 | 退出码 0/1/2 分流，`env_error` 不计 worse；阈值须实测 ≥1.5×，或 3 次采样中位数与最小值均 ≥ 阈值 |
| 28 | 用户纠正定位后只改 SKILL.md | 范例/模板/触发词/README/test-prompts 五件套同批对齐（见 `evolve.md`「定位变更五件套审计」） |
| 29 | 只读体检顺手建分支/写账本/改文件 | 只读审计零写入、零联网；发现缺陷先报告，用户说「修」才进入可变进化 |
| 30 | 用旧回执或改完文件后的旧报告冒充验收 | 改完必须重跑 `--execute` 生成新回执，再用 `--check` 复核；源码/清单哈希不符即拒绝 |
| 31 | 口头记录使用问题（「记住了」「下次注意」） | 当场跑 `python feedback/log.py add` 落 `feedback/inbox.tsv`；进化轮认领后 `set <行> --status processing/resolved --evidence` |
| 32 | 只改 skill 不同步血统与注册表 | keep 后跑 `python feedback/log.py bump`（`generation +1`）；交付/进化后 `registry.py --sync`，孤儿 skill 及时 `--adopt --seal` |
| 33 | 为提高自测分去改评分器（古德哈特刷分） | 评分器视为冻结基准；确属检查器假阴性/假阳性时，必须先写正反误判回归测试锁定边界，并在 `results.tsv` 注明未改业务质量 |
| 34 | 只写 `pangu.json` 旁路文件，不在目标 `SKILL.md` 盖盘古印记 | 运行时只加载目标 `SKILL.md`，无印记 = 使用现场不会触发落箱；新建或 `--reseal` 必须保持 `seal=ok` |
