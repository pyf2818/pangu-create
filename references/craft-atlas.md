# 领域工艺图谱（Craft Atlas）

> 「各自顶尖」的载体：每个领域有自己的顶级参照物、参数基准、独有手法——**不是一套通用美学套所有领域**。产出型 skill 锻造前先查本图谱，**F5 出厂时注册/回填**（不等 E4），让每个领域的工艺随实战累积，像物种各自演化出顶尖性状。
>
> **开放注册制**：本图谱不预设领域清单。任何新领域按「注册格式」开新节即可；没有的领域不是不能做，是先做、做完回填、沉淀成节。
>
> **深度等级判据**（L1/L2/L3 定义见 forge.md「E4 升级」）：L1 框架级（冷门领域，诚实降级）→ L2 工程级（继承同类解法 + 配方库）→ L3 专家级（代表作 + 配方库 + 真实使用进化 ≥2 轮）。

## 一节的标准格式（9 字段注册格式）

```markdown
## <领域名>（首锻造 YYYY-MM-DD | 最近回填 YYYY-MM-DD | 已锻造 N 件 | 深度 L1/L2/L3）

**North Star 参照物**：该领域公认顶尖的 1-2 个实物/作品（要有名字，能找到）
**参数基准**：从参照物拆出的量化工艺参数（≥5 项，带数值，**每项带证据指针**：实测日志/盲评记录/results.tsv 行）
**独有手法**：只有这个领域才有的做法（别的领域用了反而错）
**反模式**：该领域的 AI 俗手（一眼假的特征）
**A 层专属调研维度**：锻造该领域 skill 时 F1.1 A 层必查的维度（例：金融→监管合规；教育→认知负荷）——领域知识里最可复用的「查什么」
**典型剧本**：playbooks.md 对应预组合编号 + 该领域的变体要点
**下游 skill 索引**：该领域已锻造的 skill（名字 + lineage_id + 深度）——与 registry.tsv 互为镜像
**辨识度测试**：遮住署名，行家能否一眼认出「这是这个领域的东西」？
**更新历史**：每次回填一行（日期 + 改了什么 + 依据）
```

**回填闸**（不设荣誉制）：每次更新必须 ① 参数带证据指针 ② 更新历史记一行 ③ 当场向用户展示 diff 并确认（forge.md E4 第 5 步）。错误参数一旦回填，会经 F1.0 污染该领域后续所有锻造。

## 3D 网页 / threejs-web（2026-10-02 | 2026-10-31 | 已锻造 2 件 | L3）

**North Star 参照物**：Bruno Simon 作品集；Linear.app 产品页的滚动叙事
**参数基准**：空间锚（物体锚定地面 + 接触阴影贴图）；光锚（key 主光 2:1 填充比、色温 ≤4000K 与页面色统一）；视觉锚（一个唯一焦点，相机目标点即它）；帧率阈值 20（实测留 1.5×，阴影贴图 ≤1024²、PCF 非 PCFSoft、全屏配角材质用 Lambert/ShadowMaterial）；FPS 哨兵 + 看门狗降级横幅。证据：threejs-web results.tsv + photoreal-product F4 实测（bg 40.4、bloom 阈值 ≥1.4）
**独有手法**：hover 原理卡（3D 物件 → DOM 标注卡淡入）；grow 动画结束后冻结阴影更新省一半渲染开销
**反模式**：全屏 PBR 地面拖帧；物体悬浮无接触阴影（塑料感主因）；雾距吞主体；发光源藏在壳内；「主源+备源」CDN 伪容错（importmap 不回退）
**A 层专属调研维度**：性能预算实战（draw call / 阴影开销）；交互与渲染争帧（hover 期间降级策略）
**典型剧本**：playbooks 剧本五（真实页面冒烟）+ 美学标杆轨拆解 → art-direction.md
**下游 skill 索引**：threejs-web（L3）· polished-3d-game（L1·3D 游戏）
**辨识度测试**：遮住 UI，看光影/构图/交互仍像「被摄影过的 3D」而非「three.js 默认 demo」
**更新历史**：2026-10-31 注册格式扩 9 字段 + 补下游索引（v1.4.0 技能群管理）

## 摄影级产品页 / photoreal-product（2026-10-21 | 2026-10-31 | 已锻造 1 件 | L3）

**North Star 参照物**：Apple 产品页；Leica 官网的珠宝级棚拍
**参数基准**：光位剧本（每块高光有归属卡，无未命名高光）；接触锚点=物体最低点正下方；背景亮度 40-50/255、竖立件补支撑；bloom ≤0.25 硬上限 0.35、阈值 ≥1.4；卡 1 距离 /0.62；clip 阈值 ≤0.0009、dead=0。证据：photoreal-product results.tsv（bg 40.4、bezel 229/80/2.74、crystal 183/93/1.91、contact 22.8/48.5，盲评 6/7）
**独有手法**：光位剧本（把打光变成可指认的剧本行，高光能溯源）；表带连续体建模；玻璃高光「锐+长」双段
**反模式**：bloom 掩盖结构错误（辉光当滤镜）；地面无接触带（悬浮感）；独立页背景斑驳云块
**A 层专属调研维度**：物理光源与材质响应（IBL/布光剧本）；产品摄影构图规范（机位/景别/留白）
**典型剧本**：playbooks 剧本五 + photoreal-product 自带光位剧本库
**下游 skill 索引**：photoreal-product（L3）
**辨识度测试**：截图进产品页画廊不违和；高光能答出「哪块是哪张卡打的」
**更新历史**：2026-10-31 注册格式扩 9 字段（v1.4.0 技能群管理）

## 数据可视化网页 / csv-viz（2026-10-21 | 2026-10-31 | 已锻造 1 件 + 3 范例 | L2）

**North Star 参照物**：FT 视觉与数据新闻（charts style guide 的实践产物）；The Pudding 视觉专题
**参数基准**：单文件 ≤450KB 性能预算（实测 230KB，余量 49%）；Chart.js 4.5.1 内联 203.6KB vs ECharts 1009.9KB（5 倍体积差定 vendor 选型）；零外联请求（file:// 双击可开，CDN 主备「伪容错」在离线场景=白屏）；同输入两次构建字节一致（无时间戳/无随机序列）；失败全部可见化（F1-F12 每个失败分支有可见出路，禁文字拒答/静默白屏）；数据三件套（线端直标/条端数值/可筛选数据表）替代 hover；看门狗 3 秒降级。证据：csv-viz results.tsv（F1-F12 注入全 PASS）+ 盲评「可寄出」判定
**独有手法**：先体检后作画（列画像短路序 id→time→geo→proportion→numeric→numeric_dirty→cat；编码三步探测 BOM→utf-8 strict→gb18030→latin-1）；action title 结论句只从清洗后真实数值计算（禁编造）；「可寄出」作为最高验收标准（盲评 judge 判「能否寄出」而非「好不好看」）
**反模式**：数据只活在 hover 里（截图/打印即丢）；图型凭直觉（时间序列配饼图）；运行期改插件（Chart.js `config.plugins.push`+update → 内部 TypeError，插件必须创建时注册）；spanGaps 默认 false（日期错位补齐后 category 轴 null → 折线断线，盲评实锤）；千分位/序列号被日期正则伪解析（5 位数字 45123 → %Y%m 伪解析成 4512-03，必须限 6/8 位）；硬编码色值散落（颜色必须单源 CSS 变量）
**A 层专属调研维度**：图表编码规范（FT/BBC 风格指南）；数据清洗的脏模式（编码/日期伪解析/空值）
**典型剧本**：playbooks 剧本三（数据可视化）+ csv-viz 自带列画像短路序
**下游 skill 索引**：csv-viz（L2）
**辨识度测试**：遮住署名，行家能否认出「编辑部级数据页」（结论句标题+直标+纸感底色）而非「Chart.js 默认 demo」
**更新历史**：2026-10-31 注册格式扩 9 字段（v1.4.0 技能群管理）
