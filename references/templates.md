# 产物模板库

> F3 构建时读取。模板是骨架不是枷锁：按剧本（playbooks.md）的领域手法填充，剧本手法优先于模板默认值。

## 一、通用 SKILL.md 骨架

适用于大多数领域（产物生成类、领域专家类、浏览器自动化类的起点）：

```markdown
---
name: [skill-name]
description: |
  [一句话：这个 skill 做什么。]
  触发词：「[中文触发词1]」「[中文触发词2]」。
  模糊需求也触发：「[用户会怎么描述这个需求]」。
  English: "[trigger phrases]"。
  （只写做什么+何时用+触发词；绝不总结工作流；总长 ≤1024 字符）
---

# [Skill 名] · [一句话定位]

> [一句最能代表本 skill 方法论的核心理念]

## 铁律（违反即停）

[5-12 条硬规则，每条带为什么。从失败调研反推，只收「违反必出事故」的，软偏好归品味层]

## 执行协议（Agentic Protocol）

[问题分类表：事实型 → 先核实什么（本领域特有的核实维度）/ 方法型 → 直接执行 / 混合型 → 先取事实再套方法]
[判断原则：回答质量会因缺少最新信息显著下降的，必须先核实]

## 工作流

Phase 0: [入口分流/前置检查表]
Phase 1: [步骤，每步：输入 → 操作 → 输出；关键步骤后跟三段式失败表]
🔴 CHECKPOINT: [用户确认点]
Phase 2: ...

## 品味守则

[领域审美倾向 / AI 俗手清单（写了就扣分的默认做法）/ 推荐做法与工作示例]

## 反模式黑名单

| # | 反模式 | 为什么 / 替代做法 |
|---|--------|------------------|

## 特殊场景

[冷门输入 / 参照物模式 / 更新模式（增量更新哪些维度、调研时间标在哪）]

## 诚实边界

- [具体局限 1]
- [具体局限 2]
- [具体局限 3]
- 调研时间：[日期]，之后的变化未覆盖

## 附录：调研来源

### 一手来源（官方/本人/参照物）
### 二手来源（他人总结）
```

## 二、工程方法类骨架变体

在通用骨架上调整（playbooks.md 剧本一）：

- 铁律升级为**大写 Iron Law** 单独成节 + 「违反字面 = 违反精神」宣言
- 新增「合理化对照表」：`| 借口 | 现实 |`，素材必须来自基线测试抓到的原文
- 新增「红灯清单——出现这些念头就重来」
- 检查点改为 🛑 STOP（纪律类需要更强的停止信号）

## 三、创意产物类骨架变体（两阶段）

- 阶段一「[领域]哲学创作」：命名一个美学运动 → 4-6 段宣言（空间/色彩/材料/节奏如何表达）→ 反复强调工艺品级打磨 → 给下个阶段留解释空间
- 阶段二「按哲学表达」：反 AI 俗手清单 + 计划先行 + 对 brief 自审（「这是不是默认方案」）+ 二次精修（只协调不添加）
- 参见 canvas-design / algorithmic-art 的结构

## 四、视频/流水线类骨架变体

- 开头「状态路由表」：`| 当前状态 | 动作 |`，第一行命中即执行
- 「Hard Rules（正确性，编号背下来）」与「工作示例（品味，可偏离）」两个章节严格分离
- 自检闭环节：产出后机器验证什么（含具体命令）、上限几轮、不过怎么办
- 并行槽位节：子 agent brief 十要素模板

## 五、test-prompts.json 模板

```json
[
  {
    "id": 1,
    "type": "happy_path",
    "prompt": "[用户会真的打出来的原话，带具体路径/参数/口语]",
    "expected": "[好产出的判据，一句话]"
  },
  {
    "id": 2,
    "type": "complex",
    "prompt": "[更复杂或有歧义的场景]",
    "expected": "[判据]"
  },
  {
    "id": 3,
    "type": "failure",
    "prompt": "[易错边界场景]",
    "expected": "[应触发失败分支/诚实承认，而不是编造]"
  }
]
```

## 九、配方库模板（references/effects.md / motion-library.md）
