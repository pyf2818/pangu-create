# 通用反模式（跨领域）

> AI 创建 skill 时常见的俗手与反模式。创建新 skill 时，品味层必须编码相关反模式。
> 每条标注来源与验证次数。

---

## [AP-01] description 总结工作流

**来源**: obra/superpowers SDO
**首次提炼**: 2026-10-01
**回填次数**: 3

description 里写「Phase 1 调研 → Phase 2 提炼 → Phase 3 构建」会让 agent 抄近路跳过正文。

**替代做法**: description 只写触发条件；工作流进正文。

---

## [AP-02] 用软化措辞写关键步骤

**来源**: 盘古开天 反模式黑名单 #2 / darwin-skill rubric
**首次提炼**: 2026-10-01
**回填次数**: 3

用「建议/可以考虑/视情况/灵活把握」写关键步骤 = 指令不可执行，执行者必须推断补全。

**替代做法**: 写具体操作、参数、格式、示例。

---

## [AP-03] 检查点只靠「建议确认」措辞

**来源**: 盘古开天 反模式黑名单 #3
**首次提炼**: 2026-10-04
**回填次数**: 2

「建议确认」「请用户确认」不是检查点——AI 会合理化跳过。必须用 🔴 CHECKPOINT / 🛑 STOP 显式视觉标记。

**替代做法**: 显式 🔴 CHECKPOINT 标记 + 交互模式的阻塞闸门语义。

## [AP-04] 同上下文自评自改

**来源**: 盘古开天 反模式黑名单 #4 / darwin-skill
**首次提炼**: 2026-10-01
**回填次数**: 2

刚改完就自己评 = 系统性乐观偏差。LLM-as-judge 对细粒度差异接近抛硬币。

**替代做法**: 独立子 agent + paired 同-judge 比较。

## [AP-12] 机械按 grep 命中定红灯

**来源**: darwin-skill 运行时中立性
**首次提炼**: 2026-10-01
**回填次数**: 2

按命中行数定 P0 → 任何讲解中立性的 skill 永远自判红灯。

## [AP-13] 数配方数量冒充观感质量

**来源**: 盘古开天 案例复盘（threejs-web 81/81、web-game-craft 86.3 仍被判「一般」）
**首次提炼**: 2026-10-21
**回填次数**: 1

「配方库 ≥N 个」「≥2 个进阶效果」是原料清单，不是成品质量。加了粒子/雾/辉光只说明用了配料，不说明构图、光比、字阶、动效曲线是对的。用配料数量当验收线 = 观感闸门可被低成本满足。

**替代做法**: 观感验收必须落到**参数级**（色值/对比度/字阶/间距/光比/时长曲线），并过盲评对比（见 `references/output-quality.md` 关 2/关 3）。

---

## [AP-14] 同上下文自评记账成 paired

**来源**: web-game-craft results.tsv（79.3→86.3，eval_mode=paired-self，judge=改者）
**首次提炼**: 2026-10-21
**回填次数**: 1

没有独立 judge 时仍把记录写成 `paired`，分数照涨、照 keep。note 里承认「存在乐观偏差」不改变证据无效的事实——记账模式降级会污染整条进化链，后续所有轮次都建立在虚高基线上。

**替代做法**: 无独立 judge 一律记 `self_eval`，不得 keep、不得宣称发布级；paired 必须由不知来源的独立 judge 比较**成品**（截图/视频/页面），不是比较 SKILL.md 文本。

---

## [AP-15] 同模板换文案当成新作品

**来源**: 五个案例产出同质性复盘
**首次提炼**: 2026-10-21
**回填次数**: 1

暗底 + 青蓝/蓝紫 + 扁平几何 + 同一版栅格，换个主题文案就交付第二个 skill。用户一眼认出是同一个模子——这不是复用，是审美停滞。

**替代做法**: 交付前跑反模板测试（≥3 处实质差异：色彩角色、构图结构、材质语言、版式节奏）；首次交付前给 2-3 个**真正不同美术方向**的变体，让用户选，而不是先做一版再问。
