# 八维质量模型（Quality Dimensions）

> 核心认知：skill 的质量是多维的——功能只是其一，画面、稳定性、性能、安全、成本同样决定成败。
> 实战教训：html-to-video v1 只在「工程正确性」维度上优秀，「体验观感」维度无人负责，被用户判「太普通」。
> 本模型把「多维度全面考虑」变成管线的强制动作：**负重维度在立项时选型、侦察时对照、内核时立卡、构建时覆盖、测试时验证。**

## 八个维度

| # | 维度 | 问的问题 | 典型落点 |
|---|------|---------|---------|
| 1 | **功能完备性** | 目标场景覆盖到哪？边界场景声明了吗？ | 工作流、特殊场景节 |
| 2 | **正确性与稳定性** | 确定性有保证吗？失败了怎么办？可重跑吗？ | 铁律、失败分支三段式、降级路径 |
| 3 | **性能与效率** | 时间/帧率/token/资源预算是多少？瓶颈有预案吗？ | scripts 黑盒优化、预算表、分段策略 |
| 4 | **体验与观感** | 产出物好看/好用吗？有品味吗？ | 色板 token、视觉锚点、**配方/模式库**、正向品味标准 |
| 5 | **安全与合规** | 越权动作拦住了吗？数据/隐私/内容风险呢？ | 负面边界、[VERIFY] 标记、确认清单 |
| 6 | **可维护与可进化** | 自包含吗？有测试题/棘轮/更新模式吗？ | 三件套（test-prompts/results.tsv/git）、更新模式节 |
| 7 | **兼容与可移植** | 换个 runtime/平台还能跑吗？依赖有探测与降级吗？ | 运行时中立措辞、依赖探测、降级表 |
| 8 | **成本与规模** | 用户花的 token/时间/金钱知情吗？批量和长任务有策略吗？ | 档位披露、分段策略、缓存规则 |

## 负重维度选型（Phase 0.5 第 2 步一并完成）

不是每个 skill 都要八维全优——**负重维度**（该领域成败所系的维度）全优，**非负重维度**及格并声明即可。速判映射：

| 预组合 | 负重维度 | 说明 |
|--------|---------|------|
| 剧本一 工程方法 | 1, 2, 6 | 纪律类：正确性与可进化是生命线 |
| 剧本二 产物生成 | 1, 4, 6 | 产出类：观感与完备性定成败 |
| 剧本三 视频多媒体 | 1, 2, 3, 4 | **四维全负重**：功能、稳定、性能（帧率/渲染时长）、观感缺一不可 |
| 剧本四 领域专家 | 1, 2, 5, 6 | 判断类：合规与可溯源是生命线 |
| 剧本五 浏览器自动化 | 2, 5, 7 | 操作类：稳定性与权限边界优先 |
| 剧本六 3D/游戏 | 1, 3, 4, 6 | 创作类：性能预算与观感并重 |
| 预组合七 人物蒸馏 | 1, 5, 6 | 知识类：合规（授权/隐私）与可溯源 |

映射是起点不是终点——按定位增删（如面向发布的 skill 把 7 兼容提为负重；按 token 计费的把 8 提为负重）。

## 各阶段的落地动作

| 阶段 | 动作 |
|------|------|
| **F1.0 侦察** | 双轨吸收：**同类 skill 轨**（工程手法）+ **美学标杆轨**（观感维度的巨人：顶级作品/课程/风格指南，拆解出可复用配方）。产出**维度对照表**：每个负重维度，同类最强解法是谁、怎么实现的（完整读源码 Extract）、是否可直接继承；同类的维度短板 = 差异化机会。「站在巨人肩膀上」的具体含义：巨人已解决的维度问题整体继承，只在自己选定的方向上超越 |
| **F2 内核** | 产出**质量维度卡**：每个负重维度 → 继承的解法 + 本 skill 的标准/铁律 + 差异化声明 |
| **F3 构建** | **覆盖检查**：每个负重维度在 skill 内必须有 ≥1 个落点（铁律/工作流/scripts/references）；**产出型 skill 必须捆绑配方库**（生成性资产）；未覆盖的负重维度 = 不许出厂，非负重维度未覆盖须写进诚实边界 |
| **F4 测试** | **验证矩阵**：每个负重维度定义验证方式（机检/实测/抽帧/评分锚点/压力测试/诱导越界），跑全矩阵；观感验证分**及格线 + 惊喜线**两档；活页面的动态交互行为必须脚本化验证；某维度无法验证时明确标注验证方式与局限 |
