# 通用铁律（跨领域）

> 违反必出事故的规则。创建新 skill 时，铁律层必须覆盖与本领域相关的条目。
> 每条标注来源与验证次数——回填次数越多越可信。

---

## [IR-01] 没有基线就没有发言权

**来源**: 盘古开天 铁律1 / obra/superpowers 文档 TDD
**首次提炼**: 2026-10-01
**回填次数**: 3

测试题先行、基线先行。没看过「不带 skill 会怎么做」，就没资格声称「带了更好」。

**应用场景**: 创建任何 skill 前先写 3 道测试题并跑基线（不带 skill 回答测试题）。

---

## [IR-02] 没有失败分支的 skill 不是 skill

**来源**: 盘古开天 铁律2 / darwin-skill rubric
**首次提炼**: 2026-10-01
**回填次数**: 3

只写正向流程 = 把事故留给运行时的 AI。每个关键步骤必须写「如果 X 失败 → 一线修复 → 仍失败兜底」三段式。

**应用场景**: 工作流每个关键步骤后跟失败分支表。

---

## [IR-03] keep/revert 只信 paired 多数决

**来源**: 盘古开天 铁律3 / darwin-skill v2.1
**首次提炼**: 2026-10-01
**回填次数**: 2

绝对分数是抽样不是测量（judge 换尺噪音 ±8 分）。同一 judge 同次读两版比较，3 个 judge 奇数投票。

**应用场景**: 进化管线 E2 优化循环的 keep/revert 决策。

---

## [IR-04] 每轮只改一个维度

**来源**: 盘古开天 铁律4 / darwin-skill
**首次提炼**: 2026-10-01
**回填次数**: 2

多变量同时改，涨跌无法归因。例外：相关簇（工作流/失败分支/检查点）可同步改但需注明。

**应用场景**: 进化管线 E2 每轮选 weighted_gap 最大的一个维度。

---

## [IR-05] 60 分诚实 > 90 分编造

**来源**: 盘古开天 铁律5 / nuwa-skill
**首次提炼**: 2026-10-01
**回填次数**: 3

信息不足时宁可交付诚实标注局限的 skill，也不交付看似完美实则虚构的。但「60 分诚实」只豁免信息不足，不豁免编造。

**应用场景**: 诚实边界章节必须写 ≥3 条具体局限。

---

## [IR-06] 自包含

**来源**: 盘古开天 铁律6 / nuwa-skill
**首次提炼**: 2026-10-01
**回填次数**: 3

所有调研、脚本、参考都在 skill 目录内，复制即用。不允许引用 skill 目录外的文件。

**应用场景**: 所有 references/scripts/assets 必须在 skill 目录内。

---

## [IR-07] 批量必逐个测试

**来源**: 盘古开天 铁律7
**首次提炼**: 2026-10-01
**回填次数**: 1

一次造 N 个 skill，每个都要独立走完 F4/F5，禁止「批量生成、回头一起测」。

**应用场景**: 批量创建 skill 时每个都要独立出厂测试。

---

## [IR-08] 运行时中立

**来源**: 盘古开天 铁律8 / darwin-skill
**首次提炼**: 2026-10-01
**回填次数**: 2

不写「在某某 agent 里运行」类措辞，不硬编码单一 runtime 的路径与工具名，除非 skill 名明确绑定单一 runtime。

**应用场景**: 安装说明三层结构（自动检测 + 各 runtime 手动路径 + cat 进 context 兜底）。

---

## [IR-09] 必须走上进化

**来源**: 盘古开天 铁律10 / evolve.md 进化契约
**首次提炼**: 2026-10-04
**回填次数**: 2

交付只是第 0 代。skill 必须带进化三件套出厂（test-prompts / results.tsv / git 或备份链）。任何真实使用的负面反馈强制触发一轮进化。

**应用场景**: F5 进化精炼是出厂必经步骤，不是可选项。

---

## [IR-10] 索要参照物

**来源**: 盘古开天 Phase 0.5 第 1 步（worse 教训）
**首次提炼**: 2026-10-04
**回填次数**: 2

需求挖掘第一步永远是索要参照物：「有没有一张图 / 一个链接 / 一个产品，是你心里想要的样子？」一个参照物胜过十次追问。

**应用场景**: Phase 0.5 需求挖掘的强制动作。

---

## [IR-11] description 不总结工作流

**来源**: obra/superpowers SDO / anthropics/skills
**首次提炼**: 2026-10-01
**回填次数**: 3

description 只写「做什么 + 何时用 + 触发词」，绝不总结工作流。写了工作流摘要，agent 会只读 description 就跳过正文。

**应用场景**: frontmatter description 控制在 1024 字符内，不出现 Phase/Step 等词。
